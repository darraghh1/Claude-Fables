## Intent

Darragh's first live run (2026-10-02) worked but the band is blurry and 16 rows tall, and it disappears 30 s after each turn. He wants it sharper, half the height, always visible, and still animating while idle. Done means: an 8-row band where Claude stays the same size as today, the default pixel look drawn one art pixel per terminal pixel, and the last scene looping on screen between turns and across session restarts.

## Specification

Repo state (main 4e9ffca): renderer/frames.ts lays the SVG out at columns*8 × rows*16 CSS px, draws it at RASTER 0.5 and box-averages 4×4 blocks plus an unsharp mask down to columns × rows*2 terminal pixels. Averaging across art-pixel boundaries is the blur in Darragh's screenshot (~/Tulip-Projects/scratch/fables-live-darragh.png). A shorter box makes the stage wider in units (hooks/svg.ts:stageWidth), so simply halving rows would shrink Claude. The pixel look renders near-black in the helper at some sizes (ISS-001), so hooks/terminal/player.ts:terminalLook draws it as original. The Director clears the band LINGER_MS (30 s) after a turn (hooks/director.ts:Director.tick → host.show(null)), and register.tsx's host.show(null) stops the terminal player.

Key geometry: one art pixel is U = 4 stage units (hooks/svg.ts:U) and the stage is H = 128 units tall, i.e. 32 art pixels. A half-block band of 16 rows is exactly 32 terminal pixels tall, so at that scale one art pixel can map to exactly one terminal pixel.

Unit 1 — renderer (renderer/**, tests/cells.test.ts and any new tests/renderer*.test.ts):
1. Pixel-exact scale: render the stage at one art pixel per terminal pixel (stage width = columns*U units, full 32 px height) and sample at art-pixel centres, with no averaging or sharpening, for the pixel look. Painterly looks keep an area filter, at the same scale.
2. Crop instead of zoom: when `rows*2 < 32`, output the `rows*2`-pixel window of that full-height frame that holds the ground line and Claude's whole sprite (GROUND_Y = 104 units is art row 26). Report `scale: 1` and `cropTop` (in art pixels) on the ready line. The job protocol is otherwise unchanged.
3. Fix ISS-001 at its root so the pixel look renders the scene at every size the band uses (rows 4–16, columns 80–300).
4. smoke.ts: add a brightness/contrast assertion per look and a sharpness assertion (below), and keep every existing check.

Unit 2 — mod (hooks/terminal/**, hooks/register.tsx, hooks/director.ts only if needed, tests/terminal.test.ts, .claude-plugin/plugin.json, README.md):
1. `terminalRows` defaults to 8.
2. Always visible: on the terminal surface the last scene stays on the band after the turn ends, rather than clearing at LINGER_MS. `/fables off` still clears it. The desktop band's behaviour is unchanged (M-02).
3. Idle animation: once a scene's frames run out, the player loops its final 2 s from the cached frames with no helper running. The loop runs while the band is idle, through `$.clock` blits only.
4. Persist across sessions: store the last shown scene in `$.store`. At session.start on the terminal, render and show it, so the band is there before the first prompt.
5. Remove the terminalLook pixel→original workaround once unit 1's ISS-001 fix is on main. Pixel then goes to the helper as itself.

Derived requirements: M-01 (grep), M-02 (desktop tree unchanged; Director linger still clears desktop), M-03 does not change: the idle loop makes no model calls, as the criterion below asserts. M-04 (validate + test), M-05 (no helper alive while idle-looping; children end on off/unload), M-06 (no deps).

## Non-goals

- Quadrant/sextant glyphs: sextants are outside the BMP, which Raster refuses. Quadrants give 2 colours per 2×2 cell. Revisit only if pixel-exact half-blocks are not sharp enough for Darragh.
- Desktop app changes of any kind.
- Installing it in every session and setting CLAUDE_CODE_TMUX_TRUECOLOR: the lead does that in /persist/nixos-config after this order (home.sessionVariables), not in this repo.
