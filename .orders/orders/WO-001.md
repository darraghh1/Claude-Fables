## Intent

Claude Fables only draws in the desktop app. To draw it in a terminal (Darragh's SSH + tmux sessions on tulip), something has to turn each animated SVG scene into frames of coloured half-block cells fast enough to play live. This order builds that helper as a standalone process the mod can spawn per scene. Nothing changes for a user yet; order B wires it into the band.

## Specification

Repo state: the mod's art pipeline is pure TypeScript with no host dependencies. `sceneToSvg(scene, { width, height, look, figure })` (hooks/svg.ts:sceneToSvg) returns one self-animating SVG (SMIL); `resumeAt(svg, seconds)` (hooks/svg.ts:resumeAt) shifts every animation so the document starts at a given time; `speaksAfter(svg)` gives the bubble's delay. A taller box zooms the stage in (hooks/svg.ts:stageWidth), which the demo showed is what makes Claude legible at 40 px tall. Sample scenes live in scripts/samples.ts:SAMPLES.

The 2026-10-02 demo (/tmp/fables-pixel-demo/animate.ts) proved the look but cost ~0.3 s per frame (Chromium PNG screenshot + one ffmpeg spawn per frame). That is ~25 s per 7 s scene: too slow to run live. This order must hit the budget below; how is the engineer's call, but no per-frame process spawn and no per-frame PNG file round-trip.

Build, all under renderer/:
1. `renderer/frames.ts` — entry run as `bun renderer/frames.ts`. Reads one JSON job from stdin: `{ scene, columns, rows, look, fps, seconds }` (scene is a validated FablesScene). Renders the scene's SVG at `columns*8 × rows*16` CSS px with the speech bubble and title hidden (the mod draws those as text, order B), samples it at `t = i/fps` for `i < fps*seconds`, downsamples each frame to `columns × rows*2` pixels with sharpening, and writes one NDJSON line per frame to stdout: `{"i":n,"t":seconds,"cells":"<base64>"}`. `cells` is exactly the Raster encoding from the plugin types (RasterProps.cells): `columns*rows` little-endian u32 triplets `[0x2580 '▀', top pixel 0x00RRGGBB, bottom pixel 0x00RRGGBB]`. First line `{"ready":true,"columns":c,"rows":r,"speaksAfter":s}`; on failure one line `{"error":"..."}` on stderr and exit 1.
2. Browser: headless Chromium driven over the DevTools protocol using bun's built-in WebSocket/fetch to 127.0.0.1 only (`--remote-debugging-port=0`, port read from stderr/DevToolsActivePort), its own temp `--user-data-dir`. Binary from env `CHROMIUM`, else `chromium` on PATH. The helper kills the browser and removes its profile dir on normal exit, on SIGTERM/SIGINT, and when stdout closes (EPIPE).
3. `renderer/cells.ts` — pure function `packHalfBlocks(rgb: Uint8Array, columns, rows): string` (base64), no I/O, so it is unit-testable under `claude plugin test`.
4. `renderer/smoke.ts` — the verify script described in Acceptance; prints timings.

Derived requirements: M-01 is met by loopback-only CDP and no other network use (grep criterion). M-05 by the helper owning the browser's lifetime (kill criteria). M-06 by bun built-ins only, no package.json. M-02, M-03, M-04, M-07 are the mod's concerns and are scoped in order B; M-04 is still checked here so existing tests stay green.

## Acceptance

- [ ] bun renderer/smoke.ts exits 0 after rendering SAMPLES[0] at 200 columns × 20 rows, 12 fps, 7 s: exactly 84 frame lines plus one ready line, each frame's cells decoding to 200*20*12 bytes.
- [ ] The same smoke run's wall-clock time from spawn to last frame, Chromium launch included, is ≤ 8 s on tulip; the script prints it and fails above 8 s.
- [ ] The smoke run sees animation: at least 10 of the 84 frames have distinct cells strings.
- [ ] Every cell's code point in the smoke frames is 0x2580 and every colour has bits 24–31 clear (valid Raster encoding).
- [ ] The smoke script sends SIGTERM to a second helper 1 s into a render; within 2 s no process with that helper's --user-data-dir remains (checked with pgrep -f) and the dir is deleted.
- [ ] With CHROMIUM=/nonexistent the helper exits 1 within 2 s with one JSON error line on stderr (asserted by the smoke script).
- [ ] tests/cells.test.ts: packHalfBlocks on a 2×2-pixel image returns the exact expected u32 triplets (▀, top colour fg, bottom colour bg) for both cells.
- [ ] No network beyond loopback: every URL literal in renderer/ is ws://127.0.0.1 or http://127.0.0.1 (grep -rnoE '(ws|https?)://[^"'\'' ]+' renderer/ shows nothing else).
- [ ] No install step: there is no package.json with dependencies, and renderer/ imports only node:*, bun, and relative paths (grep of import lines).
- [ ] claude plugin validate . passes and claude plugin test . passes with the 60 existing tests plus the new cells test.

## Non-goals

- Wiring into the mod, the band, caption text, config: WO-002.
- Sextant (2×3) glyphs: half-blocks first; revisit only if Darragh wants more detail after seeing the band live.
- 256-colour quantisation: tulip's tmux sets terminal-features *:RGB, so 24-bit is assumed.
- Windows/macOS Chromium discovery: the target is tulip.
