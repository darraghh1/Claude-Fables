## Intent

Today the mod draws only in the desktop app's Code tab; in a terminal it still pays for Sonnet/Haiku scenes and draws nothing. After this order the same scenes play above the prompt in a terminal: the art as coloured half-block cells, the caption typed out as real text beside Claude, the chapter tag as text. The desktop app's band does not change.

## Derived requirements (from archetypes: claude-code-mod · always rows)

_Inlined always rows only (pass --all-requirements at "bp order new" to inline all rows)._

- R-1 [claude-code-mod] always: M-01 Host I/O through $ — The hooks module reaches the host only through $ nouns ($.process, $.fs, $.model, $.ui, $.store, $.clock); helper processes open no network connection except loopback to a browser they started.
- R-2 [claude-code-mod] always: M-02 Surface-gated drawing — Each ui.render branch narrows e.surface; a change for one surface leaves every other surface's tree byte-identical.
- R-3 [claude-code-mod] always: M-03 No model spend without a drawer — The narrator does not call $.model.complete when no mounted surface can draw the scene it would produce.
- R-4 [claude-code-mod] always: M-04 Validate and test — 'claude plugin validate .' passes and 'claude plugin test .' passes from the repo root, with new behaviour covered by a *.test.ts.
- R-5 [claude-code-mod] always: M-05 No orphan children — Every $.process.spawn child (and anything it starts, e.g. a browser) ends when its stream loop ends, the scene is replaced, or the module unloads.
- R-6 [claude-code-mod] always: M-06 Zero install step — Helpers use only bun built-ins and host binaries; no package.json dependencies, because a plugin install runs no package manager.

## Specification

Repo state: hooks/register.tsx draws only for `e.surface === 'desktop'` in its `ui.render` AbovePrompt hook (returns `next(e)` otherwise), but its `session.start` hook starts the Director's 1 s tick on every surface, so the terminal pays for scenes it never draws. `host($, band)` in register.tsx adapts the Director (hooks/director.ts:Director) to the engine: `show(scene)` stores the scene in the `fables.scene` atom, `speaksAfter(scene)` draws the SVG to time the bubble. The Director already guarantees one scene on the band at a time, held until read (`readUntil`), so the terminal path only has to follow `fables.scene`.

Engine facts this order relies on (plugin types, build 2.1.288): the terminal element table has `Raster` and `Image` but no `Svg`; AbovePrompt is raised on terminal and desktop only and its props carry `bodyColumns` and `maxRows` (fullscreen slot capped at half the terminal); `Raster` takes `key, columns, rows, cells` (base64 u32 triplets `[codePoint, fg, bg]`, code points width-1 BMP, colours 0x00RRGGBB or 0x01000000 for default); `$.ui.blit({ requestId, key, cells })` repaints a mounted Raster without a render pass, `requestId` being the band's (read from the ui.render event); `$.process.spawn({ argv, input })` takes stdin once and streams stdout pieces (not lines), and ending the `for await` loop kills the child; `$.plugin.root` is the mod's folder.

Build:
1. `hooks/terminal.ts` (or `hooks/terminal/*`): a per-session player.
   - On each new scene (and on a box change), end the previous render loop, then `$.process.spawn({ argv: ['bun', `${root}/renderer/frames.ts`], input: JSON job, env: { CHROMIUM } })` with `columns = bodyColumns`, `rows = min(terminalRows, maxRows - 1)`, `fps = 12`, `seconds = ceil(readMs(scene)/1000)`. Split stdout pieces into NDJSON lines and keep frames by index.
   - A `$.clock.every(Math.round(1000/12))` playback picks frame `floor((now - shownAt) * 12)` (the newest one rendered if that one is not in yet), loops the final 2 s once past the end, overlays the caption and title as text cells, and calls `$.ui.blit` only when the composed cells differ from the last blit.
   - Caption overlay: a box-drawn bubble (`╭─╮│╰╯`, ink #222222 on paper #f4efe2) wrapped at 36 characters, beside Claude's final position (hero `to` %), clamped inside the band; it types out at `TYPE_SECONDS_PER_CHAR` starting at the helper's `speaksAfter`. Title, when present, as plain text top-left on the art.
2. register.tsx: the AbovePrompt hook gains a `terminal` branch returning `<Raster key="fables" columns rows cells>` with the current composed frame (a dark frame with the bubble until the first frame lands). The desktop branch is untouched (M-02).
3. Fallback (M-07): if the spawn rejects, the helper writes an error line, or no frame arrives within 5 s, the terminal branch draws the caption as text in a bordered Box instead, and logs the reason once with `$.ui.log(..., { to: 'debug' })`.
4. Config in .claude-plugin/plugin.json userConfig: `terminalRows` (default 16) and `chromiumPath` (default "chromium"); types/index.d.ts updated if the contract needs it. README: one short "Terminal" section saying what it needs (bun, Chromium, a 24-bit-colour terminal).

Derived requirements: M-01 (all host access through `$`, grep criterion), M-02 (desktop tree byte-identical test), M-04 (validate + test), M-05 (spawn loop ended on scene change, off, and module unload; test with a mocked spawn), M-06 (no dependencies added). M-03: after this order both surfaces that raise AbovePrompt draw, so the narrator always has a drawer; the order keeps the tick unchanged and records that reasoning rather than gating it.
